# LuckySpinAPI

Учебный проект по МДК.03.02 «Управление проектами»: веб-API слот-игры на **C# / ASP.NET Core**. Игра идёт на виртуальные кредиты, реальные деньги и платежи в проекте не используются.

## Назначение

Игрок получает стартовый баланс, делает ставки и видит результат вращения трёх барабанов. Оператор (в планах) следит за игроками и может блокировать нарушителей.

## Целевые пользователи

|Роль|Что делает|
|-|-|
|Игрок|Смотрит баланс, делает ставки, смотрит историю игр|
|Оператор|Смотрит список игроков, блокирует и разблокирует игроков|

## MVP

* Просмотр баланса игрока (`GET /api/slots/balance/{userId}`)
* Ставка и вращение (`POST /api/slots/spin`)
* Начисление выигрыша: три одинаковых символа, выигрыш ×5
* Проверка ставки: ноль, отрицательное значение и ставка выше баланса отклоняются

Не входит в MVP: пополнение и вывод реальных денег, регистрация с паролями и JWT, мобильное приложение, внешняя база данных. Подробности в [паспорте проекта](docs/PROJECT_CHARTER.md).

## Критерии готовности MVP

1. API запускается командой `dotnet run`
2. Реализованы четыре функции MVP
3. Не менее 5 автоматических тестов проходят
4. Отрицательная ставка не меняет баланс
5. README описывает запуск и правила игры

## Быстрый старт

Требуется .NET SDK 3.1 (в проекте `netcoreapp3.1`, обновление платформы запланировано в [TECH-03](docs/BACKLOG.md)).

```bash
cd LuckySpinAPI
dotnet run
```

Сайт откроется на `https://localhost:5001`, интерфейс игры находится в `wwwroot/index.html`.

## API

|Метод|Адрес|Описание|
|-|-|-|
|GET|`/api/slots/balance/{userId}`|Баланс; новый игрок создаётся с 1000 кредитов|
|POST|`/api/slots/spin`|Тело `{"userId": 1, "betAmount": 100}`; ответ: `combination`, `newBalance`, `isWin`, `winAmount`|

Правила игры сейчас: символы 🍒, 🍋, 777; три одинаковых дают выигрыш ставка × 5. База данных работает в памяти (InMemory) и очищается при перезапуске.

## Текущее состояние и известные проблемы

* Ставка `betAmount <= 0` не проверяется: отрицательная ставка увеличивает баланс (требование FR-04, история US-03, задача первой итерации).
* `Services/SlotEngine.cs` не используется, а его правила отличаются от `SlotsController` (TECH-01).
* Запись истории игр (`GameLog`) не ведётся, роли, блокировка и пароли в модели `User` пока не используются.
* Остался шаблонный `WeatherForecast`, `launchUrl` ведёт на него.
* Автоматических тестов нет (TECH-02).
